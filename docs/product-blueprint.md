# 产品蓝图与建设节奏

## 建设策略

平台按“前端定义体验 + 后端契约同步 + 核心闭环前后端一起做”推进。前端负责让项目经理、现场人员和公司管理层看懂业务路径，后端从第一天提供稳定接口和审计边界，Agent 只做辅助决策，不自动修改核心业务数据。

当前优先级是项目层：先把单项目的进度、质量、成本、安全、资料五条线跑通，再将公司层作为真实项目数据的聚合入口。

## 角色与范围

项目层用户：

- 项目经理
- 生产经理
- 质量负责人
- 安全负责人
- 商务经理
- 资料员
- 现场人员

公司层用户：

- 公司管理层
- 区域负责人
- PMO

V1 范围：

- 项目仪表盘
- 智能问答
- 进度管理
- 质量管理
- 成本管理
- 安全管理
- 资料管理
- 待办、通知、审计

## 阶段路线

1. 第 0 阶段：产品蓝图与数据契约，3-5 天。
2. 第 1 阶段：前端主体验 + 后端轻服务同步，1-2 周。
3. 第 2 阶段：进度 + 安全 + 资料深闭环，3-5 周。
4. 第 3 阶段：质量与成本闭环，2-4 周。
5. 第 4 阶段：真实后端工程化，4-6 周。
6. 第 5 阶段：公司层管理接入，2-4 周。

## 默认边界

- V1 不接正式 ERP、BIM、OA，只预留连接器接口。
- V1 不做高度自治，所有关键业务动作由人确认。
- 技术管理先并入质量技术线，二期再拆独立模块。
- 当前仓库继续作为本地演示和工程化雏形，后续替换为数据库、队列、对象存储和真实模型网关。
